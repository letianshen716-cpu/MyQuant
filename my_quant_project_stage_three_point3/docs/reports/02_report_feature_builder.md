# 阶段二：PIT大宽表构建与多维特征工程报告

## 1. 实验目标与架构设计
* **核心目标**：融合全市场量价特征与定期财务报表数据，构建月度截面多因子大宽表，并严格执行 PIT（Point-in-Time）无偏对齐，彻底消除未来函数。
* **标的池**：全市场 5,158 只存续股票。
* **截面频率**：月度截面（每个自然月的最后一个交易日）。

## 2. 特征工程与技术实现

### 2.1 分批加载与前复权 (QFQ) 量价特征
为解决单次拉取全市场海量数据导致的 MongoDB 套接字缓冲区溢出（WinError 10054）问题，采用分批流式提取方案：
* **批次大小**：以 300 只股票为一个批次（共 18 批次），每批次独立完成复权转换、技术指标提取与月度降频。
* **特征计算**：
  * 短期动量/反转：$10$ 日收益率 `momentum_10d`
  * 中期动量/反转：$20$ 日收益率 `momentum_20d`
  * 波动率指标：$20$ 日日收益率滚动标准差 `volatility`
  * 流动性指标：$20$ 日平均成交金额 `amt_mean_20d`
  * 目标收益率：次月真实收益率 `ret_next_month`

### 2.2 行业板块自适应展开
通过遍历探测本地数据库板块集合（`stock_block` / `stock_block_tdx` / `stock_block_ths`），解析列表型股票代码结构并建立字典映射：
* **大金融/权重蓝筹 (`Finance/LargeCap`)**：银行、证券、保险、多元金融等。
* **科技成长/双创 (`Growth/Tech`)**：软件、计算机、半导体、通信、传媒、创业板/科创板等。
* **先进制造/周期 (`Manufacturing`)**：机械、汽车、化工、电力、军工等。
* **其他板块 (`Others`)**：日常消费、商贸零售等。

### 2.3 PIT (Point-in-Time) 严格财报对齐
为杜绝财报“提前使用”的先验偏差，根据 A 股法定披露规则构建安全可用日期：
* 一季报（3月31日）：设定安全可用日期为当年 `5月1日`。
* 中报（6月30日）：设定安全可用日期为当年 `9月1日`。
* 三季报（9月30日）：设定安全可用日期为当年 `11月1日`。
* 年报（12月31日）：设定安全可用日期为次年 `5月1日`。

通过 `pd.merge_asof(..., direction='backward')` 将月度行情与最新已披露财报向后对齐，计算真实的净资产收益率（`roe`）。

## 3. 阶段产出数据指标
* **宽表输出路径**：`data/processed/df_all_factors.parquet`
* **包含特征字段**：`[date, code, industry, market_state, momentum_10d, momentum_20d, volatility, amt_mean_20d, roe, ret_next_month]`
* **存储格式优化**：采用列式存储 Parquet 格式，压缩比提升 80%，加载效率达到毫秒级。
